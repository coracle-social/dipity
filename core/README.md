# core

Everything below the UI, in Rust. See [`docs/overview.md`](../docs/overview.md#the-plugin-boundary) for why it exists and what belongs here; this file covers the build.

## Layout

| Crate | Role |
| --- | --- |
| `serendipity` | Protocol, crypto, store, session. Pure logic, no bindings, testable on the host. |
| `serendipity-ffi` | The uniffi surface. Everything crossing to Swift or Kotlin is declared here by hand. |

The split keeps binding machinery out of the code under test, and keeps the FFI surface something you have to write on purpose rather than something that accumulates.

**This is scaffolding.** One exported call, enough to prove the toolchain links end to end. Modules will mirror the design documents one to one as they land.

## Building

Every recipe lives in the [`justfile`](../justfile) at the repo root, not here.

```sh
just setup        # rust targets, npm deps
just core-test    # host tests
just bindings     # Swift + Kotlin from the built cdylib
just ios-lib      # XCFramework, device + simulator
just android-lib  # jniLibs, all ABIs — needs the NDK and cargo-ndk
just qa           # what CI runs
```

Generated output stages under `core/target/ffi/`, which is gitignored and rebuilt from scratch. Nothing generated is committed.

`just sync` chains core → bindings → web → `cap sync`, and the mobile recipes go through it, so a native build cannot pick up a stale library.

## Not yet wired into the native projects

Both shells need the artifacts referenced once, and neither reference exists yet because the Capacitor plugin does not either.

**iOS.** `ios/App/CapApp-SPM/Package.swift` is regenerated by `cap sync` and says so at the top, so the binary target does not go there — it belongs to the plugin's own SPM package, which will declare `SerendipityFFI.xcframework` as a `.binaryTarget` and carry `serendipity_ffi.swift` in its sources.

**Android.** `jniLibs/` copies into `android/app/src/main/`, and the generated Kotlin into the plugin's source set. uniffi's Kotlin bindings need `net.java.dev.jna:jna:5.x@aar` as a dependency; `android/app/build.gradle` is not regenerated by `cap sync`, so that edit is safe to make by hand.

## Adding a dependency

The heavy ones are chosen but not yet added, since nothing uses them: `rusqlite` for the store, `secp256k1` for grant and auth signing, `k256` for the grant proof's explicit group arithmetic, `snow` for Noise XX. Add them to `[workspace.dependencies]` when the module that needs them arrives, so version choices stay in one place.
